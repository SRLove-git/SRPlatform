# SRPlatform 路线图

路线图的原则是：每个阶段都必须有一个能运行、能演示、能验证的闭环，不做“先写一万行再测试”的假进展。

## Phase 0：平台骨架

目标：启动一个窗口，显示地面和一个方块。

交付标准：

- 固定步长主循环可以运行。
- 最小 ECS 能创建和更新实体。
- 渲染层能显示基础几何体。
- 工程结构支持后续加入物理、电路、脚本模块。

## Phase 1：刚体物理

目标：让物体真正“掉下来、撞到地、能滑动”。

交付标准：

- 重力、质量、速度、角速度。
- 盒体与地面碰撞。
- 接触与摩擦。
- 简单约束，例如轮子绕轴旋转。

## Phase 2：基础电路

目标：独立验证电路求解能力。

交付标准：

- 电阻、电容、电感、电压源、电流源。
- 节点电压法求解。
- 输出节点电压和支路电流。
- 与一个已知电路结果对照。

## Phase 3：第一台能跑的小车

目标：打通“电池 -> 电机 -> 轮子 -> 地面”的完整链路。

交付标准：

- 电池供电。
- 直流电机模型，含电阻、电感、反电动势、扭矩。
- 车轮与地面摩擦产生运动。
- 用户脚本可以设置电机目标值。
- 能观察电压、电流、转速、位移。

## Phase 4：无人机与传感器

目标：验证空气动力和反馈控制。

交付标准：

- 简化螺旋桨推力与反扭矩。
- 无人机四轴受力。
- IMU、编码器、距离传感器。
- 用户可以写 PID 或简单控制逻辑。

## Phase 5：Mod 系统

目标：用户不再只能玩内置物体。

交付标准：

- 从外部加载 3D 模型。
- 从外部加载元件和电路定义。
- 从外部加载脚本。
- Mod 包可以创建车辆、无人机、机器人实体。
- 类似 MC Mod 的注册与依赖机制。

## Phase 6：编辑器与学习体验

目标：从“能仿真”升级为“好用、可教学”。

交付标准：

- 场景、电路、脚本可视化编辑。
- 波形和传感器面板。
- 仿真暂停、步进、回放。
- 示例课程：RC 小车、循迹车、四旋翼、简单机械臂。

## 建议的长期边界

- 先不要做流体、布料、破坏等高级物理，除非教学内容明确需要。
- 先不要做多人联机，回放和确定性仿真更优先。
- 先不要追求真实 MC 兼容，先做“类似 MC Mod 的扩展理念”，而不是复制 MC 引擎。
